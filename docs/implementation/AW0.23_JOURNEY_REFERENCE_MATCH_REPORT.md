# AW0.23 Journey Reference Match Pass

Статус: реализовано локально, без Git commit.

## Результат

Существующая вкладка Journey приведена к композиции утверждённого
референса без второго параллельного экрана:

- слева находится компактная карточка выбранного прохождения;
- справа используется одна горизонтальная лента этапов;
- под этапами отображаются связанные события;
- выбранный этап открывается в единой карточке дневника;
- нижняя панель разделена на статистику, график настроения и
  предварительную оценку.

Режимы «сетка/список» отсутствуют. При переключении вкладок и обновлении
данных сохраняются экземпляр Journey, выбранный этап и позиция ленты.

## Использованные компоненты UI Kit

- `VeloraStageCard`;
- `VeloraActionCard`;
- `VeloraScrollArrow`;
- `VeloraRatingSelector`;
- `VeloraMoodSelector`;
- `MoodChart`;
- `IconProvider`;
- semantic tokens `Colors`, `Spacing`, `Radii`, `Dimensions`, `Typography`.

UI Kit остаётся presentation-only и не обращается к SQLite, repositories
или application services.

## Визуальные изменения

- До: низкая плотность и текстоподобные этапы. После: крупные карточки
  фиксированной геометрии с отдельными статусом, временем и оценкой.
- До: события выглядели повторяющимися подписями. После: на линии остаются
  содержательные события с SVG-иконками, максимум два и индикатор `+N`.
- До: редактор этапа воспринимался как разрозненная форма. После: изображение,
  дневник, теги, настроение, оценка и быстрые действия объединены в один блок.
- До: нижняя аналитика была визуально тонкой. После: три равноправные зоны с
  мотивирующей метрикой, MoodChart и предварительной оценкой.
- До: настроение могло визуально выводиться из оценки. После: график использует
  только явный стабильный `mood_id`; отсутствие настроения нейтрально.

## Хранение mood ID

Личное настроение этапа хранится только в `user.db`, в таблице
`journey_stage_moods` с ключом `(playthrough_id, stage_id)`.

Старые базы расширяются идемпотентным `CREATE TABLE IF NOT EXISTS` при
инициализации storage. Запись, изменение и очистка выполняются через
`DoomVerticalSlice -> UserUnitOfWork -> JourneyStageMoodRepository`.
`catalog.db` не содержит таблиц или полей персонального настроения.

## Известные ограничения

- Скриншоты создаются в Qt offscreen и проверяют геометрию/композицию;
  системные шрифты и общая тема полноценного окна проверяются при ручном
  запуске Velora.
- До появления MediaService карточка этапа использует завершённый
  placeholder изображения; пользовательский screenshot не записывается
  фиктивно.
- Быстрые действия подготавливают существующий редактор записи. Отдельные
  специализированные модели достижений и медиа этим проходом не создавались.
